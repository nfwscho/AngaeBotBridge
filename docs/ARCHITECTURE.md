# 앙개봇 2.0 — 통합 플랫폼 설계 기준서

> **단일 아키텍처 문서.** 모든 신규 콘텐츠/메뉴/운영 설계는 이 파일에 업데이트합니다.
> 2026-11-06 앙개봇 2.0 통합 플랫폼 재설계안을 기준으로 정리했으며 이전 메뉴 설계 v1/v2 전문을 하단에 보존합니다.

## 1. 프로젝트 목표

최초 '카카오톡 메시지를 정확히 받고 응답'하는 기능 검증 단계를 넘어, 콘텐츠를 독립적으로 개발·배포할 수 있는 **개인 AI 기반 모듈형 카카오톡 플랫폼**으로 발전합니다.
- 사용자는 단축어와 숫자 메뉴만으로 원하는 콘텐츠에 빠르게 진입
- 신규 콘텐츠는 공통 명령/메뉴/AI/DB/운영 서비스를 재사용하고 다른 콘텐츠와 결합하지 않음
- 서버·소스·GitHub·테스트·로그·백업·배포는 사용자 콘텐츠와 분리된 운영 체계로 관리
- 현재 정상 동작하는 주식/AI/Android 수신·발신/배터리/로그/UI/설정/DB 기능을 절대 임의 제거하지 않음
- 실행하지 못하는 기능은 '개발 예정'으로 정확히 안내하고 실제 시세·일정·날씨를 꾸며내지 않음

## 2. 3계층 플랫폼 구조

### A. 콘텐츠 계층 — 사용자에게 제공되는 기능

| 콘텐츠 | 단축어 | 독립 하위 모듈 |
| --- | --- | --- |
| 주식 | `주` | 메모리7, 관심종목 그룹, 한·미·일 시세, 기업·반도체 분석, 뉴스/공시, 조건 알림(향후) |
| 배드민턴 | `민` | 기술/강좌, 영상 라이브러리, 관절·라켓·셔틀 분석, 훈련 계획/기록 |
| 요리 | `요` | 레시피 DB, 조리시간/분량, 냉장고 재료, 식단 추천, 장보기 |
| 여행 | `여` | 여행지/계절/경로·지도, 일정, 숙소·맛집, 저장된 여행 |
| 종친 | `종` | 종친회 소개, 행사, 계보, 회비 안내(개인정보 인증 설계 후 조회/수정) |
| 날씨 | `날` | 오늘/내일/주간 예보, 위치 설정; 현재 날씨 데이터 API 연동은 개발 예정 |

영어(`영`)는 사용하지 않아 2026-11-06 메인 메뉴에서 제외했습니다. 요청 시 별도 콘텐츠로 다시 등록할 수 있습니다.

### B. 공통 플랫폼 계층 — 모든 콘텐츠가 재사용

- Android 알림 수신 NotificationListenerService, KakaoTalk RemoteInput 답장, 기존 ON/OFF/알림 권한/허용 방·발신자·SQLite SHA256 지문 중복 방지
- Core 인증 FastAPI, request_id 기반 SQLite 중복 실행 방지, events/jobs 로그
- 공통 메뉴/명령 라우터, 정확한 한 글자 호출어·문자열 경계, 방·발신자별 5분 선택 세션 및 세션 상한
- **앙패스(AngaPass)** — `주 2`, `주 2 2`, `앙 1 2 2`, `설 2`처럼 공백으로 숫자를 잇는 최대 5단계 메뉴 점프; 중간 단계는 재조회/중복발신하지 않음
- AI 엔진: OpenAI/Ollama 선택형, 기본 OFF. 대화 요약/질문 및 사용자별 문맥 지원
- 시세/검색/DB·파일/알림/스케줄러 및 향후 콘텐츠 서비스 추상화
- 일관된 응답 푸터: `원문 응답 → 담당 기능 모듈명 → 소스 파일 경로 → S20+ 배터리`
- 배포된 Core와 앱 버전·실제 브랜치/커밋 확인, 사용자별 로그 범위 및 민감 정보 비노출

### C. 개발 및 운영 인프라 계층

- S20+ Termux Python Core, runit/SSH/watchdog/포트, 향후 미니 PC 서버 이전/분리
- GitHub 기능 브랜치, PR, Actions, 자동 테스트, 배포 검증, 커밋 SHA/버전 체계
- Python Core/Android Bridge 관리, 기존 운영 데이터 보호, 안전한 배포/rollback/백업
- 미니 PC에서 Ollama 오픈소스 AI 모델을 별도 서비스로 구동하는 장기 확장
- 웹 관리자 대시보드(미구현): 서비스·메모리·오류·모듈 상태, 설정·로그, 배포 현황 등
- 운영자 권한이 필요한 정보(회원 계보, 회비, 서비스 재시작, GitHub 수정)는 공개 카톡 메뉴로 직접 노출하지 않음

## 3. 현재 실행 시스템 구조 (구현된 부분)

```text
[카카오톡 사용자]
   ├─ 앙/주/민/요/여/종/날/설 또는 숫자 1~10/0/00, 앙패스
   ↓
[Galaxy S20+ Android Bridge]
   ├─ NotificationParser: 채팅방·발신자·메시지
   ├─ BotConfig: ON/OFF, 허용 목록, 로컬 UI/로그
   ├─ CommandParser: 호출어/로컬 상태/도움말
   ├─ MenuSelectionGate: 5분 메뉴 선택
   ├─ PythonBridgeClient: 인증 localhost:8765
   └─ ModuleSourceFormatter + BatteryStatusReporter → RemoteInput
   ↓
[Termux Python Core / FastAPI]
   ├─ main.py: 인증, 라우팅, 세션 연결/중복 차단/SQLite 로그
   ├─ selection_menu.py: 홈/콘텐츠/주식/설정 메뉴·앙패스
   ├─ market.py: 시세/메모리7 공급자
   ├─ watchlists.py: 종목 그룹·소유권
   ├─ history.py: 과거 거래일·실현변동성·분석
   ├─ ai_engine.py: AI 질문/요약
   ├─ ops.py: 서버/배포/설정/통계/오류 조회
   ├─ module_info.py: API 응답 담당 소스 식별자
   └─ commands.py: 계산/시간/서버상태
   ↓
[동작이 허용된 외부 시세/AI API]
```

## 4. 실제 카카오톡 메뉴·단축어

```text
🤖 앙개봇 메인 메뉴 (앙)
1. 📈 주식
2. 🏸 배드민턴
3. 🍳 요리
4. 🧭 여행
5. 🌳 종친
6. 🌤 날씨
7. ⚙️ 설정·운영
※ 1~10 선택 · 0 이전 · 00 홈 · 5분 유효
```

`상`: 기존 Android 로컬 상태 및 Core health의 **실제 배포 브랜치/커밋**.
`도`: 기존 도움말.
`주 분 삼성전자`, `주 목록` 등 기존 주식 단축어 호환 유지.

운영 설정 `설` 메뉴:
1. 서버·서비스 상태
2. 배포 버전·커밋 (Core 로컬 .deploy-info.json 기록)
3. 최근 실행 로그 (같은 방/발신자의 Python Core 실행 결과)
4. 설정 현황 (읽기 전용)
5. 명령 통계
6. 최근 오류

읽기 전용 메뉴에서 인증키, 채팅 내용, 다른 사람의 로그, GitHub 권한, 서비스 재시작/파괴적 동작은 제공하지 않습니다.

| 주식 메모리7·한미일 주가/지연 시세 | `core/app/market.py` |

| 서버/설정/배포 기록/로그/진단 | `core/app/ops.py` |
| AI 질문/요약/AI상태 | `core/app/ai_engine.py` |
| 계산/시간/기본 서버 상태 | `core/app/commands.py` |
| Android 로컬 상태/도움말/테스트 | `app/src/main/java/kr/co/angaebot/bridge/CommandParser.kt` |
| 모듈명/소스 경로 출력 | `app/src/main/java/kr/co/angaebot/bridge/ModuleSourceFormatter.kt` |
| 배터리 정보 | `app/src/main/java/kr/co/angaebot/bridge/BatteryStatusReporter.kt` |
| Core 기능 모듈 ID 선택 | `core/app/module_info.py` |
| 전체 Core API 라우팅/인증 | `core/app/main.py` |

**각 카카오톡 응답에서 표시되는 모듈/경로는 실제 처리 분야를 알려주는 소유권 지표**입니다. 응답 형식과 소스 위치가 바뀌면 module_info.py/ModuleSourceFormatter.kt 매핑과 테스트를 같이 수정합니다.

GitHub 최신 `main`이 아닌 S20+에서 확인된 `core/.deploy-info.json`의 배포 SHA/브랜치를 `상`에 표시합니다. 기록 누락 시 미확인으로 안내하고 현재 브랜치라고 추측하지 않습니다.

## 6. 점진적 목표 디렉터리 구조 (설계, 아직 미구현)

대규모 분산 마이크로서비스보다 **단일 GitHub 저장소 + Modular Monolith(모듈형 모놀리스)**를 추천합니다. 영상·추론 등 고부하만 향후 별도 서비스로 분리합니다.

```text
AngaeBotBridge/
├── app/                          # 기존 Android Bridge UI/알림
├── core/
│   ├── app/
│   │   ├── main.py                # 기존 API 호환
│   │   ├── platform/              # 목표: 메뉴·명령 라우터/모듈 레지스트리
│   │   ├── features/
│   │   │   ├── stocks/            # 기존 market/watchlists/history 이관 대상
│   │   │   ├── badminton/         # 영상, 자세
│   │   │   ├── cooking/           # 레시피
│   │   │   ├── travel/            # 지도·계획
│   │   │   ├── clan/              # 종친
│   │   │   └── weather/           # 기상 API
│   │   └── services/              # 공통 AI, DB, 검색, 스케줄러
│   └── tests/                     # 모듈별 독립 회귀 테스트
├── ops/                           # 향후 서버/백업/운영 대시보드
├── docs/
│   ├── ARCHITECTURE.md
│   ├── OPERATIONS.md
│   ├── TEST_PLAN.md
│   └── UPGRADE.md
└── CHANGELOG.md
```

위 경로는 **미래 목표**로, 현재 운영 중인 `core/app/*.py` 파일을 한 번에 이동하거나 앱을 재설치하지 않습니다. 공통 인터페이스/테스트 작성 → 기존 구현 단계별 연결 → 안정화 후 점진적 이동 순서를 따릅니다.

## 7. 서버와 AI 확장 설계

- 현재는 Galaxy S20+의 Termux Core와 Android Bridge를 유지합니다.
- 향후 약 100만원 내외 미니 PC나 Mac mini에 독립 Python 서비스와 Ollama 추론을 올려 AI/영상 분석/주식 데이터 수집을 분산할 수 있습니다.
- AI 엔진은 7B~8B 양자화 모델부터 실측 평가하고, 최신 시세는 AI 기억이 아닌 검증한 거래소/공시/뉴스 도구를 통해 제공합니다.
- 공통 DB는 초기 SQLite와 백업을 유지하고 필요 시에만 PostgreSQL로 이전하며 기존 사용자 데이터를 파괴하지 않습니다.
- Android Bridge와 서버는 인증·권한 검사를 적용하고, 민감한 데이터는 공개 채팅방 상태 응답에 넣지 않습니다.
- 로컬 AI 장애 시에도 메뉴/계산/기존 시세/운영 기능은 정상 작동하도록 독립성을 유지합니다.

## 8. 개발·운영·GitHub 관리 규칙

1. 기능 요구 → 기능 브랜치 → 최소 코드 변경 → 모듈별·전체 회귀 검사 → 해당 SHA CI 성공 확인.
2. 기존 GitHub Actions의 Python 3.12/Core 테스트, Android Kotlin/APK, Windows PowerShell 5.1/7 검사를 그대로 유지.
3. 같은 기능 커밋에서 PR+push 중복 workflow를 방지하기 위해 `feature/**`/main push 검사만 사용하고 PR에는 HEAD SHA 검사 상태를 사용.
4. `main` 병합은 **'앙개봇 메인' 채팅에서 사용자 승인 후**에만 수행.
5. main 병합 후 전체 CI 확인 후 S20+ 1회 PowerShell 배포로 Core/APK 업데이트.
6. 배포 성공과 CI 성공은 구별하고, 실제 카카오톡 응답 화면의 버전·브랜치·모듈·배터리를 확인.
7. 운영 로그/SQLite/.env/앱 사용자 데이터·허용목록을 보호하고 배포 실패 시 rollback/원인 보고.
8. Python 프로그램 맨 위에는 모든 기존/신규 기능·로그·UI 보존 사항을 자세히 주석으로 남김.
9. 새 릴리스마다 새 문서 파일을 만들지 않고 `CHANGELOG.md`와 고정 문서 네 개에 **최신 내용을 위로** 추가.

## 9. 개발 로드맵

- 1단계: 사용자 호출어/홈·콘텐츠·번호·이전 메뉴·앙패스 확립 (구현됨)
- 2단계: 기능 모듈 표시/실배포 브랜치·커밋 상태/문서 단일화 (이번 개발)
- 3단계: 주식 하위 기능 정리, 시세 데이터 제공자 분리/검증, 종목 분석 고도화
- 4단계: 서버/소스·GitHub PR·CI·로그·백업/운영자 관리 도구 표준화
- 5단계: 배드민턴→요리→여행→종친→날씨 등 독립 콘텐츠 개발
- 6단계: AI 추론 서버/스케줄러/도구 호출·웹 관리 대시보드 (추후 확장)

## 앙패스(AngaPass)

정확한 숫자 메뉴 경로를 공백으로 연결하여 최대 5단계까지 이동한다.

| 메시지 | 이동 |
| --- | --- |
| `주 2` | 주식 → 메모리7 시세 조회 |
| `주 2 2` | 주식 → 메모리7 시세 목록의 2번 종목 분석 |
| `앙 1 2 2` | 홈 → 주식 → 메모리7 → 2번 분석 |
| `주 6 2` | 주식 → 종목별 분석 → 2번 하이닉스 분석 |
| `설 2` | 설정·운영 → 배포 버전·커밋 |
| `설 3` | 설정·운영 → 현재 방/발신자 최근 명령 로그 |
| `날 1` | 날씨 → 오늘 날씨 (실제 날씨 데이터 연동은 개발 예정) |

일반 `0`은 이전 메뉴, `00`은 홈으로 돌아가는 기존 동작을 유지한다.
메뉴 점프는 1개의 인증된 FastAPI 명령으로 전달되어 jobs/events 로그에 1회 기록되며, 중간 시세 목록을 네트워크로 조회하거나 카카오톡으로 여러 번 전송하지 않는다. 최종 시세 또는 분석 명령만 기존 모듈에서 실행한다. 중간 관심그룹·관심목록 선택은 동일 방·발신자 보관 데이터를 조회하고 번호 1~10의 실제 표시 순서를 사용한다. 임의 텍스트/부작용 명령/5단계 초과는 제한한다.

## 읽기 전용 설정·운영

```text
⚙️ 설정·운영 메뉴
1. 서버·서비스 상태
2. 배포 버전·커밋
3. 최근 실행 로그
4. 설정 현황 (읽기 전용)
5. 명령 통계
6. 최근 오류
※ 조회 전용 · 설정 변경은 관리자 화면에서만
```

- 서버 상태: 기존 service_status/runit 상세상태, SSH, Core 가동시간 재사용
- 배포: Core 런타임 버전, 실제 배포 후 기록한 Git SHA 앞 12자, 브랜치, 시각, 동일 실행에서 Android APK 설치 여부를 조회; 기록이 없다면 "미기록" 표시
- 로그: Python Core SQLite jobs의 동일 room/sender 최근 6건 결과 및 시각만 표시. 로그의 argument/result, AI 질문 원문, 토큰, Android 로컬 SQLite 로그는 일반 카카오톡에 노출하지 않는다. Android 상세 로그는 기존 앱 관리 화면 이용
- 설정: AI ON/OFF 요약과 5분 세션, 사용자별 메뉴 범위 등 비밀이 아닌 상태만 표시
- 통계·최근오류: 기존 scoped ops 함수 재사용
- 이 단계의 설정·운영 메뉴는 **읽기 전용**이다. 서버 서비스 변경, GitHub 변경, 토큰·환경변수 수정, 로그 삭제 등 관리자 권한 기능은 포함하지 않는다.

## 신뢰 및 보호

- 메뉴 번호·한 글자 호출어는 Android 허용방/허용발신자 확인 이후만 처리한다.
- 동일 원문 알림은 기존 SHA-256 request_id 및 SQLite dedup으로 재실행 방지한다.
- 숫자 선택은 정상 Core의 menu_active를 받았고 RemoteInput 답장을 요청한 경우에만 5분 동안 허용된다.
- 앙패스는 숫자 전체 경로를 입력한 단일 명시적 명령이다. 5분 전 메뉴 세션이 없어도 실행 가능하되 Core API 토큰 인증과 방·발신자 확인을 통과해야 한다.
- 날씨 하위 항목은 현재 플레이스홀더이며 허위 기온/예보를 표시하지 않는다.
- Core API 버전 0.6.0, Android Bridge v0.4.8(versionCode 12). 기존 주식·AI·배터리·설정·Android 앱 데이터 구조 유지.

## 배포

기능 브랜치 `feature/global-shortcut-menus-20261106`, main 병합 금지(별도 승인).
최신 커밋의 GitHub Actions Python/Android/Windows PowerShell 전체 회귀 성공 시에만 배포.
Android APK 변경이 있으므로 `-InstallAndroid`를 사용하며, 기존 설치 데이터 삭제 없이 검증한다.
프로그램 배포 후 Core 로컬 `.deploy-info.json`에는 non-secret commit SHA/branch/time/Android 업데이트 여부만 원자적으로 기록한다.

# 앙개봇 2.0 단축 메뉴·콘텐츠 경계 설계 (v1)

## 목표

기존 카카오톡 알림 기반 Android Bridge, 인증된 Python FastAPI, 읽기 명령, 관심종목, AI, 배터리 표시, SQLite 작업·이벤트 로그, 5분 숫자 선택을 모두 보존하면서 콘텐츠별 단축 메뉴 진입을 제공한다.

## 호출어 (정확히 일치하는 메시지만 인식)

| 메시지 | 동작 | 구현 단계 |
|---|---|---|
| `앙`, `앙개야`, `앙개야 메뉴` | 메인 메뉴 | 구현 |
| `주` | 기존 주식 메뉴 | 기존 구현 유지 |
| `주 분 삼성전자`, `주 목록` | 기존 주식 분석·관심목록 단축어 | 기존 구현 유지 |
| `민` | 배드민턴 | 카테고리 메뉴 구현·세부 기능 준비 중 |
| `요` | 요리 | 카테고리 메뉴 구현·세부 기능 준비 중 |
| `여` | 여행 | 카테고리 메뉴 구현·세부 기능 준비 중 |
| `종` | 종친 | 카테고리 메뉴 구현·세부 기능 준비 중 |
| `영` | 영어 | 카테고리 메뉴 구현·세부 기능 준비 중 |
| `상` | 기존 Android 로컬 상태 | 기존 로컬 명령 유지 |
| `도` | 기존 Android 로컬 도움말 | 기존 로컬 명령 유지 |

단축 콘텐츠는 메시지 전체가 한 글자인 경우에만 인식한다. 사용자 지정 호출어가 정확히 일치하면 기존 호출어 처리 우선이다. `요리`, `영어`, `앙상블` 같은 일반 메시지를 단축어로 오해하지 않는다.

## 숫자 이동

- `1`~`10`: 현재 메뉴에서 번호 선택 (최종 엔진은 고정 메뉴 정의 및 정식 명령에만 연결)
- `0`: 한 단계 이전으로 이동. 최상위 홈에서 `0`은 홈 재표시
- `00`: 즉시 홈으로 이동
- 선택 가능 시간: 5분, 방·발신자별 격리, 최대 200 세션
- Android에서 숫자 명령은 먼저 허용 방·발신자 확인, 인증된 Python 응답에서 `menu_active=true`가 확인되고 카카오톡 `RemoteInput` 회신이 요청되었을 때만 활성화
- 활성 세션이 없거나 다른 사람의 방/발신자라면 숫자 선택을 실행하지 않음
- 서버 재시작 시 메뉴는 소멸. 사용자 데이터는 삭제하지 않음

## 홈 구조

1. 주식 — 기존 주식 메뉴로 연결
2. 배드민턴 — 강좌·기술 / 영상 라이브러리 / 자세 분석 / 훈련 기록
3. 요리 — 요리 추천 / 레시피 찾기 / 보유 재료 활용 / 장보기
4. 여행 — 여행지 추천 / 여행 일정 / 이동 경로 / 맛집·숙소
5. 종친 — 종친회 안내 / 행사 일정 / 계보·자료 / 회비 안내
6. 영어 — 생활 영어 / 회화 / 어휘 / 복습

현재 미개발 하위 콘텐츠는 '개발 예정' 텍스트와 같은 메뉴를 반환한다. 계보·회비 등 개인정보가 필요한 콘텐츠의 실제 조회, 변경·등록·삭제, 원격 PC 제어, 주식 주문, 자동 발신은 구현하지 않는다.

## 소스 경계

- `CommandParser.kt`: 정확한 단축 호출어를 허용된 명령으로만 변환
- `MenuSelectionGate.kt`: 기존 5분/스코프 TTL과 숫자 파싱; 공통 `메뉴 선택`으로 연결
- `KakaoNotificationListener.kt`: 기존 허용목록·SQLite dedup·로그/RemoteInput; `menu_active`만 사용
- `PythonBridgeClient.kt`: 기존 인증 토큰과 `/v1/commands` HTTP JSON 프로토콜 유지
- `selection_menu.py`: 주식 메뉴·시세표 선택 상태를 재사용하는 통합 홈 및 미구현 콘텐츠 표시
- `main.py`: 같은 jobs/events 저장 및 request_id 중복 방지 경로로 메뉴 실행
- `market.py`, `watchlists.py`, `history.py`: 기존 구현 유지

## 이후 아키텍처 작업

콘텐츠별 실제 기능을 개발할 때에는 고유한 **menu_id**와 **action_id**로 등록하고 Python Core 공통 메뉴 레지스트리에 연결한다. 현재 단계에서는 소규모 정적 메뉴이며, 콘텐츠 파일/데이터베이스/관리자 권한을 새로 생성하지 않는다. 각 콘텐츠는 주식, 배드민턴, 요리, 여행, 종친, 영어 단위의 독립 테스트 및 문서와 함께 순차적으로 분리한다.

## 배포·검증 규칙

신규 브랜치 `feature/global-shortcut-menus-20261106`에서 Python 전체 회귀, Android 메뉴 테스트 및 디버그 APK 빌드, 배포 스크립트 검사를 GitHub Actions로 진행한다. `main` 병합은 메인 채팅에서 사용자 승인 후 진행한다. 단축 호출어를 실제 카카오톡에서 수신하려면 새로운 Android APK 설치가 필요하며, Core만 업데이트해서는 한 글자 단축어가 작동하지 않는다.

## 보안 주의

카카오톡 알림의 방 이름 및 발신자 이름은 강력한 신원 인증 수단이 아니므로 종친회 회원·계보 개인정보, 회비 처리, 서버·GitHub·소스 제어 명령은 일반 채팅 메뉴에 노출하지 않는다. 해당 기능들은 별도의 인증·인가 설계 완료 후 개발한다.
